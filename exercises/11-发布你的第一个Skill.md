# 11 | 练习：发布你的第一个 Skill

## 🎯 练习目标

- 掌握完整的 Skill 开发到发布流程
- 能独立开发并发布一个可用的 Skill
- 理解 agentskills.io 的生态

---

## 📋 练习要求

### 基础任务（必做）

**把以下团队 SOP 转成完整的 SKILL.md 文件：**

**SOP 来源**：技术方案评审流程（来自 CTO 制定的标准）

```
技术方案评审流程：

1. 提出阶段
   - 工程师撰写技术方案文档
   - 方案应包含：背景、目标、技术选型、风险评估、实施计划

2. 评审阶段
   - 发送评审邀请给相关团队
   - 评审内容：
     a. 技术选型是否合理（考虑扩展性、成本、团队能力）
     b. 风险是否已识别，是否有应对措施
     c. 与现有系统是否冲突
     d. 实施计划是否可行（时间线、资源）

3. 决策阶段
   - 评审通过：标注"Approved"，可以开始实施
   - 需要修改：列出具体修改意见，标注"Request Changes"
   - 否决：说明原因，标注"Rejected"

4. 归档阶段
   - 将评审结果同步到技术方案文档
   - 在 #tech-design 频道通知结果
```

**要求**：
- 包含完整的 YAML 元数据（name + description）
- 包含 When to Use / When NOT to Use
- 包含完整的 Steps（评审顺序不能乱）
- 包含 Output Format

**2. 发布检查清单**

在你准备发布 Skill 之前，检查以下项目：

- [ ] YAML 元数据格式正确（name、description）
- [ ] 触发条件包含具体关键词
- [ ] Steps 结构化、不模糊
- [ ] Output Format 明确
- [ ] 至少一个完整 Example
- [ ] 本地测试通过

### 进阶任务（选做）

**调研你团队的最重要 3 个 SOP，然后选择其中 1 个，写成完整的 SKILL.md，并在本地完成测试。**
