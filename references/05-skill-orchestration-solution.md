# 05 | 参考答案：Skill 编排与组合

## 📋 基础任务参考答案

### 任务 1：Skill 关系分析

**并行部分：**
- `code-review` 和 `test-runner` 可以并行——审查代码和运行测试不互相依赖

**串行部分：**
- `deployment` 必须等待 `code-review` 和 `test-runner` 都通过
- `monitoring-check` 是 deployment 之后的下游

**执行顺序图：**

```
用户："帮我把这个新功能上线"

              ┌──────────────────────┐
              │   code-review       │ ← 并行
              │   （审查代码）        │
              └──────────┬─────────┘
                         │
┌────────────────────────┼────────────────────────┐
│                        │                        │
▼                        ▼                        │
┌──────────────────────┐  ┌──────────────────────┐
│    test-runner        │  │   （如果有问题）      │
│    （运行测试）        │  │   → 返回修改          │
└──────────┬───────────┘  └──────────────────────┘
           │
           ▼（全部通过）
┌──────────────────────┐
│     deployment        │ ← 串行：必须等上面都通过
│     （执行部署）        │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│   monitoring-check   │ ← 串行：部署后检查
│   （检查监控）        │
└──────────────────────┘
```

### 任务 2：Skill 冲突分析

**是否冲突？**

是的，这两个 Skill 冲突。它们对"先测试还是先写代码"有相反的假设。

**修正方式：**

在一个 Skill 里区分不同模式：

```markdown
## Steps

### TDD 模式（当用户提到 "TDD" 或 "测试驱动" 时）
1. 先写测试
2. 再写代码

### 传统模式（默认）
1. 先写代码
2. 再补测试
```

### 任务 3：触发优先级设计

通过描述暗示优先级：

```yaml
---
name: database-schema
description: 数据库设计规范。当用户明确提到"数据库设计"、"schema"、"表结构"、"migration"时优先触发。
---

---
name: api-design
description: 通用 API 设计原则。适用于更广泛的系统设计讨论。
---
```

**优先级策略：**
- 更具体的 Skill（database-schema）描述更精确，触发词更明确 → 优先匹配
- 更通用的 Skill（api-design）作为兜底
