# 05 | 实战：从团队 SOP 到 Skill

## 🎯 学习目标

- 能把真实工作中的 SOP 转成 Agent Skill
- 掌握从"经验"到"Skill"的全流程
- 理解 Skill 在团队中的应用价值

---

## 📖 概念讲解

### 最佳实践：把自己团队的 SOP 写成 Skill

Skill 最大的价值不是"通用模板"，而是**把你团队的工作方式固化下来**。

每个团队都有自己的规范：
- 代码审查流程
- API 设计原则
- 代码规范
- 部署步骤

把这些写成 Skill，AI 就能按你们的方式工作，而不是按它自己的习惯。

### 实战案例：把"新功能上线"SOP 转成 Skill

#### 原始 SOP（来自团队 wiki）

```
新功能上线检查清单：

1. 代码审查
   - 安全检查（SQL 注入、XSS、密钥）
   - 测试覆盖率 ≥ 80%
   - 无 console.log 提交

2. 测试环境验证
   - 功能测试通过
   - 回归测试通过

3. 文档更新
   - API 文档更新
   - README 更新（如有必要）

4. 部署
   - 通知团队
   - 执行部署脚本
   - 监控错误率
```

#### 转成 Skill

```yaml
---
name: feature-launch
description: 新功能上线 SOP。当用户说 "上线"、"deploy"、"发布功能"、"launch" 时触发。
---

# Feature Launch SOP

## When to Use
当用户要求将功能上线到生产环境时使用。
包括：新建功能、重大修改、需要上线的修复。

## When NOT to Use
- 本地测试不需要触发
- 仅涉及文档修改不需要此 SOP（用 doc-update Skill）

## Prerequisites
确认以下事项已完成：
- [ ] 代码审查通过
- [ ] 测试覆盖率报告已生成
- [ ] 部署脚本已在仓库中

## Steps

### Step 1：代码审查（必须）
按以下清单逐项检查：
1. **安全**：SQL 注入、XSS、硬编码密钥、API 泄露
2. **测试**：测试覆盖率 ≥ 80%，无失败的测试
3. **日志**：无 console.log / debugger 提交
4. **格式**：通过 lint 检查

### Step 2：测试环境验证
1. 在测试环境执行功能测试
2. 执行回归测试套件
3. 记录测试结果

### Step 3：文档更新
1. 更新 API 文档（如 API 有变更）
2. 更新 README（如有必要）
3. 更新 CHANGELOG

### Step 4：通知团队
1. 在 #deployments 频道发送部署通知
2. 包含：功能描述、测试结果、风险评估

### Step 5：执行部署
1. 运行部署脚本
2. 监控前 5 分钟错误率
3. 如错误率 > 1%，立即回滚

## Output Format

上线报告必须包含：
```
## 上线报告

### 功能
[功能名称和描述]

### 审查结果
- [x] 安全检查通过
- [x] 测试覆盖率 XX%
- [ ] lint 检查（列出未通过项，如有）

### 测试结果
- [x] 功能测试通过
- [ ] 回归测试（X 通过，Y 失败）

### 部署状态
[成功/失败/回滚]

### 备注
[需要关注的特殊事项]
```

## 团队应用场景

| 团队 SOP | 转成 Skill |
|---------|-----------|
| 代码审查流程 | code-review |
| API 设计规范 | api-design |
| 新功能上线 | feature-launch |
| Bug 报告格式 | bug-report |
| 技术方案评审 | tech-design-review |
| 数据库变更 | db-migration |
| 代码合并规范 | pr-merge |

---

## 💡 价值总结

把团队 SOP 写成 Skill 的价值：

1. **知识沉淀**：专家经验不再在专家脑子里，而是变成可复用的文件
2. **一致性**：无论谁用 AI，每次工作方式一致
3. **新人友好**：新成员借助 AI 就能按团队规范工作
4. **持续改进**：Skill 可以版本管理，团队迭代优化

---

## 📝 章节回顾

**记住：**

1. **Skill 的最大价值**：把团队 SOP 变成可复用的知识包
2. **转换流程**：原始 SOP → 结构化步骤 → SKILL.md
3. **团队沉淀**：Skill 是团队知识管理的载体，不只是提示词
