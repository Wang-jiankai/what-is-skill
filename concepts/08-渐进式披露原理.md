# 08 | 渐进式披露原理

## 🎯 学习目标

- 理解渐进式披露的设计思想
- 掌握 Level 1/2/3 的加载时机
- 学会利用渐进式披露优化 Skill 性能

---

## 为什么需要渐进式披露？

AI 的上下文窗口是有限的。如果每次触发 Skill 都把全部内容塞进去：
- 上下文很快被撑爆
- AI 需要在海量信息中找重点
- 响应变慢，成本变高

**渐进式披露（Progressive Disclosure）** 解决了这个问题：平时只加载最核心的信息，必要时再加载详细内容。

---

## 三个 Level

```
Level 1（始终加载）：YAML 元数据（name + description）— AI 判断何时触发
Level 2（按需加载）：SKILL.md 正文（Instructions）— 详细操作步骤
Level 3（必要时加载）：scripts / references — 脚本和参考资料
```

### Level 1：YAML 元数据（始终加载）

```yaml
---
name: code-review
description: 团队代码审查 SOP。当用户说 "review this PR" 或 "审查代码" 时触发。
---
```

**作用**：AI 每次对话都会检查所有 Skill 的 name 和 description，决定是否触发这个 Skill。

**设计要点**：
- `description` 要足够具体，让 AI 能准确判断触发时机
- 建议包含触发关键词（用户可能说的话）

### Level 2：SKILL.md 正文（按需加载）

只有当 Skill 被触发时，AI 才会加载完整正文。

**作用**：包含核心的 Instructions、步骤、输出格式等。

**设计要点**：
- 正文结构要清晰（When to Use / Steps / Output Format）
- 长度控制在合理范围（建议 < 5k tokens）

### Level 3：scripts / references（必要时加载）

当 Instructions 需要更详细的参考资料时，才加载。

```
my-skill/
├── SKILL.md              # Level 2
├── scripts/              # Level 3：自动化脚本
│   └── run-tests.sh
├── references/           # Level 3：详细参考资料
│   └── security-checklist.md
└── assets/               # Level 3：模板、图片
    └── report-template.md
```

**作用**：
- `scripts/`：需要确定性执行的自动化脚本
- `references/`：详细的技术文档、清单、模板
- `assets/`：输出时需要的模板文件

**使用场景**：
```markdown
## Steps

1. 执行安全检查（见 `references/security-checklist.md`）
2. 运行测试脚本：`scripts/run-tests.sh`
3. 生成报告（模板在 `assets/report-template.md`）
```

---

## 渐进式披露的优势

| 方式 | 上下文占用 | 加载速度 | 适用场景 |
|------|----------|---------|---------|
| 全量加载 | 高 | 慢 | 简单、固定的 Skill |
| **渐进式披露** | **低** | **快** | **所有 Skill** |

---

## 实际示例

### 一个完整的 Skill 目录

```
code-review/
├── SKILL.md
├── scripts/
│   └── generate-report.sh
├── references/
│   ├── security-checklist.md
│   ├── performance-checklist.md
│   └── output-template.md
└── assets/
    └── report-template.md
```

### SKILL.md 中的引用

```markdown
## Steps

### 1. Security Check
按 `references/security-checklist.md` 执行安全审查。

### 2. Performance Check
按 `references/performance-checklist.md` 执行性能审查。

### 3. Generate Report
运行 `scripts/generate-report.sh`，使用 `assets/report-template.md` 作为输出模板。
```

---

## 避免的问题

### 1. 所有内容堆在 SKILL.md 里

```
❌ 把 checklist、模板、示例全部写在 SKILL.md 正文中
→ 正文过长，加载慢

✅ 按需拆分到 references/ 和 assets/
→ 正文简洁，按需加载
```

### 2. 引用不存在或路径错误的资源

```markdown
✅ 正确引用：
按 `references/security-checklist.md` 执行

❌ 错误引用：
按同级目录的 checklist 执行（未指定路径）
```

---

## 📝 章节回顾

**记住：**

1. **Level 1 = 始终加载**：YAML 元数据，决定是否触发
2. **Level 2 = 按需加载**：SKILL.md 正文，核心 Instructions
3. **Level 3 = 必要时加载**：scripts / references / assets

**渐进式披露的核心思想**：不让 AI 处理它现在不需要的信息。
