# 01 | 什么是 Agent Skill？

## 🎯 学习目标

- 理解 Agent Skill 解决的核心问题
- 掌握 Agent Skill 与 MCP 的本质区别
- 理解"渐进式披露"的设计原理

---

## 📖 概念讲解

### Agent Skill 是什么？

**Agent Skill** 是一份结构化的"标准作业指导书"（SOP），以 `SKILL.md` 文件的形式打包领域知识，供 AI 在执行特定任务时加载使用。

> **简单理解**：Skill 就是一份"专家培训手册"——你把某个领域的最佳实践写下来，AI 看了就知道该怎么稳定地完成这类任务。

### 为什么会诞生 Agent Skill？

当前 AI Agent 有一个核心问题：**不稳定**。

你可能有这样的体验：

```
第一次：AI 审查代码，发现了 SQL 注入漏洞 ✅
第二次：同样的 AI，同样问代码审查，没发现 XSS 漏洞 ❌
第三次：换了个问法，AI 完全跳过了安全审查 ❌
```

问题不在模型，在于**没有把"怎么做"的流程固化下来**。

**没有 Skill 的 AI**：
> 模型很聪明，但每次都靠"即兴发挥"。你得祈祷它的推理路径这次是对的。

**有 Skill 的 AI**：
> 模型严格按照你的 SOP 走。安全审查 → 逻辑审查 → 性能审查，步步不落。

### Skill vs MCP：不是竞争，是协作

| | MCP | Agent Skill |
|--|-----|------------|
| **解决什么问题** | AI 能访问什么外部工具 | AI 应该怎么做某类任务 |
| **本质** | 连接协议（让 AI 能触碰外部世界） | 知识打包（让 AI 知道正确流程） |
| **类比** | USB-C 接口——能插上锅碗瓢盆 | 米其林厨师手册——告诉你火候、步骤、摆盘 |
| **文件形式** | 服务器进程，通过 stdio 通信 | `SKILL.md` 文件，文本格式 |
| **谁来提供** | 开发者写代码 | 领域专家写文档 |

**两者可以组合**：

```
MCP：让 AI 能访问数据库
Skill：告诉 AI 怎么安全地查数据、怎么格式化输出
```

### 渐进式披露：Smart 的设计

Skill 用了"渐进式披露"（Progressive Disclosure）——不会一次性把全部内容塞进 AI 的上下文：

| 层级 | 内容 | 何时加载 |
|------|------|---------|
| **Level 1** | YAML 元数据（name + description） | 始终加载，AI 判断是否触发 |
| **Level 2** | SKILL.md 正文（Instructions） | 触发后加载，核心流程 |
| **Level 3** | scripts / references | 必要时加载，脚本和参考资料 |

**为什么这样设计？**
- Level 1 几乎不消耗 token，AI 可以预判断该不该触发
- Level 2 通常 < 5k tokens，足够完整
- 避免上下文爆炸，同时保证 AI 能获取完整知识

## 💡 生活中的类比

想象你是一家餐厅的**经理**，要培训新来的厨师（AI）：

**没有 SOP 的培训：**
> 你跟厨师说："好好做菜！注意火候！用心做！"
> 结果：厨师这次做了川菜，下次做了法餐，第三次做了分子料理——完全看心情。

**有 SOP 的培训：**
> 你给厨师一本操作手册："做宫保鸡丁，先滑锅、再炒花生、最后加鸡丁，每步 30 秒，火候中火。"
> 结果：厨师每次都按手册来，质量稳定。

**Agent Skill 就是那本操作手册。**

---

## 📝 章节回顾

**记住这三个关键点：**

1. **Skill 解决的是"做对的事"**
   不依赖模型即兴发挥，而是把专家经验固化下来

2. **MCP 是手，Skill 是技能书**
   两者互补，不竞争

3. **渐进式披露**
   Level 1 判断触发 → Level 2 核心流程 → Level 3 按需加载

**核心公式：**

```
Agent Skill = YAML 元数据（name + description）+ Markdown 正文（Instructions）+ 可选脚本
```
