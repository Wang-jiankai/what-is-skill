# 11 | 发布你的第一个 Skill

## 🎯 学习目标

- 掌握完整的 Skill 开发到发布流程
- 能独立开发并发布一个可用的 Skill
- 理解 agentskills.io 的生态

---

## 发布流程概览

```
Step 1：选择一个有价值的场景
Step 2：编写 SKILL.md
Step 3：本地测试
Step 4：发布到 agentskills.io
Step 5：收集反馈，持续迭代
```

---

## Step 1：选择一个有价值的场景

好的 Skill 来源：

1. **团队重复性工作**：你们每周都在做但没文档化的 SOP
2. **个人效率工具**：你自己常用的工作流程
3. **行业最佳实践**：某个领域的专业流程

**评估标准**：
- 这个流程是否重复发生？
- 这个流程是否可以被结构化？
- 其他团队/人也需要这个吗？

### 选题练习

思考你工作中的这三个问题：
1. 你的团队最费时的重复性工作是什么？
2. 你自己最常用的工作流程是什么？
3. 你希望 AI 能帮你自动做什么？

任选一个作为你的第一个 Skill 选题。

---

## Step 2：编写 SKILL.md

以"会议纪要 Skill"为例：

### 2.1 确定触发条件

```yaml
---
name: meeting-notes
description: 会议纪要生成 SOP。当用户说"记一下"、"会议纪要"、"生成 notes"、"总结会议"时触发。
---
```

### 2.2 设计 Steps

```markdown
## When to Use
当用户提供会议讨论内容、录音、转录、或链接时触发。

## Prerequisites
- 用户提供的会议内容
- 如果是会议链接，先总结会议内容

## Steps

### 1. 提取关键信息
- 会议主题
- 参会人员
- 讨论的要点（按话题分）
- 做出的决定
- 分配的行动项（Owner + Deadline）

### 2. 生成结构化纪要

按以下格式输出：

```
## 会议主题
[主题名称]

## 参会人员
- [姓名]

## 讨论要点
### 话题 1
- 要点 1
- 要点 2

### 话题 2
...

## 决定
1. [决定内容]

## 行动项
| 行动项 | Owner | Deadline |
|--------|-------|----------|
| ...    | ...   | ...      |
```

### 3. 审核与补充
- 检查格式完整性
- 补充遗漏的关键信息
```

### 2.3 完整的 SKILL.md

```yaml
---
name: meeting-notes
description: 会议纪要生成 SOP。当用户说"记一下"、"会议纪要"、"生成 notes"、"总结会议"时触发。
---

# Meeting Notes SOP

## When to Use
当用户提供会议讨论内容、录音、转录、或链接时触发。

## Prerequisites
- 用户提供的会议内容
- 如果是会议链接，先总结会议内容

## Steps

### 1. 提取关键信息
- 会议主题
- 参会人员
- 讨论的要点（按话题分）
- 做出的决定
- 分配的行动项（Owner + Deadline）

### 2. 生成结构化纪要

按以下格式输出：

## 会议主题
[主题名称]

## 参会人员
- [姓名]

## 讨论要点
### 话题 1
- 要点 1
- 要点 2

### 话题 2
...

## 决定
1. [决定内容]

## 行动项
| 行动项 | Owner | Deadline |
|--------|-------|----------|
| ...    | ...   | ...      |

### 3. 审核与补充
- 检查格式完整性
- 补充遗漏的关键信息

## Examples

### Example 1：触发 Skill
```
用户：帮我总结一下这个会议
AI：[加载 meeting-notes Skill] → 按 SOP 生成结构化纪要
```

### Example 2：输出示例
```
## 会议主题
Q2 产品规划讨论

## 参会人员
- 张三
- 李四
- 王五

## 讨论要点
### 需求优先级
- 确认 Q2 核心功能：A、B、C
- A 功能最重要，优先开发

### 技术方案
- 讨论了微服务改造方案
- 决定先做 POC

## 决定
1. Q2 主攻 A 功能
2. 微服务 POC 3 月底完成

## 行动项
| 行动项 | Owner | Deadline |
|--------|-------|----------|
| 完成 A 功能 PRD | 张三 | 3/15 |
| 微服务 POC | 李四 | 3/31 |
```

## Output Format
必须严格按照上述格式输出，缺少任何一项都要标注"[待补充]"
```

## Step 3：本地测试

### 3.1 安装 Skill

```bash
mkdir -p ~/.claude/skills/meeting-notes
# 保存 SKILL.md 到该目录
```

### 3.2 测试触发

```
/skills
```

确认 meeting-notes 出现在列表中。

### 3.3 实际使用测试

```
用户：帮我生成会议纪要
会议内容：
[粘贴实际的会议内容或描述]
```

### 3.4 验证输出

检查：
- [ ] 输出格式是否符合预期？
- [ ] 内容是否准确？
- [ ] 触发是否正确（不该触发时有没有触发）？

### 3.5 迭代优化

根据测试结果调整 SKILL.md：
- 触发条件是否准确？
- 步骤是否清晰？
- 输出格式是否完整？

---

## Step 4：发布到 agentskills.io

访问 agentskills.io 查看具体的：
- 提交流程
- 格式要求
- 审核标准

### 准备发布文件

```
meeting-notes/
├── SKILL.md
├── scripts/           # 如果有
├── references/      # 如果有
└── README.md        # 可选，说明 Skill 的用途
```

### 检查清单

- [ ] SKILL.md 格式规范
- [ ] name 和 description 清晰
- [ ] Steps 结构化、不模糊
- [ ] Output Format 明确
- [ ] 至少一个完整 Example
- [ ] 本地测试通过

---

## Step 5：持续迭代

发布不是终点，而是起点。

**收集反馈**：
- 其他人用这个 Skill 有什么问题？
- 触发条件是否准确？
- 步骤是否需要优化？

**定期更新**：
- 根据反馈优化 Instructions
- 补充 Edge Cases
- 更新 Examples

---
